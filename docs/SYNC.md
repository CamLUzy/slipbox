# 多端互联：局域网同步方案（计划，v1.2）

> 状态：方案设计中，还没有实现。欢迎在 [Discussions](https://github.com/CamLUzy/slipbox/discussions) 里提意见。

## 一句话

两台设备都打开卡片盒，在同一个 Wi-Fi 下，**在其中一台点“同步”，另一台就作为主机**。两台之间直接加密传输，几秒钟后两边的卡片盒完全一致。不经过任何服务器，也不需要账号。

## 原则

- **没有服务器**：设备之间在局域网里直连，卡片不经过第三方。
- **加密且认人**：只和配对过的设备同步，传输全程加密，别人在同一个 Wi-Fi 里也看不到内容。
- **不丢内容**：两边都改过同一张卡片时，较旧的那份变成“冲突副本”放进收件箱，而不是被覆盖。
- **一套合并逻辑**：合并规则写在共享的 `web/js/ops.js` 里（纯函数、有单元测试），Mac、Windows、iPhone 用的是同一份代码；原生外壳只负责发现设备和加密传输。
- **同步前先备份**：每次合并前自动备份当前卡片盒，出了问题可以退回。

## 用户流程

### 第一次：配对（每对设备只做一次）

1. 两台设备都打开卡片盒，进入 **设置与数据 → 设备与同步**，“在局域网中可被发现”默认在这个页面打开时开启。
2. 列表里会出现同一个 Wi-Fi 下的其他卡片盒设备（显示设备名，比如“lu 的 MacBook Air”“Windows 台式机”“iPhone”）。
3. 点其中一台 → 两台设备屏幕上同时出现一个 **6 位校验码**。两边的数字一样，就点“确认配对”。
4. 配对完成后双方记住对方，以后同步不需要再确认。

校验码由加密握手的结果算出：如果有人在中间冒充，两边看到的数字就会不同。这和蓝牙配对时比对数字是同一个原理。

### 日常：点一下就同步

1. 两台设备都打开卡片盒（iPhone 需要在前台）。
2. 在任意一台点 **同步**（侧栏底部或“设备与同步”页面）。
3. **点的这台是发起方，另一台是主机**：发起方把自己改过的卡片发给主机，主机合并后把结果发回来，两边写入同样的内容。
4. 结束后显示一份摘要：新增 N 张、更新 N 张、冲突副本 N 张、编号顺延 N 张，点开可以看到具体是哪些卡片。

### 同步哪些卡片盒

- 卡片盒按内部 ID 对应（重命名不影响）；两边同名但从未同步过的卡片盒会询问“合并为一个”还是“分开保留”。
- 主机上有、本机没有的卡片盒会列出来，勾选后一起拉过来。

## 合并规则

每张卡片已经有 `uid`（全局唯一）、`updatedAt`、`deleted`。新增三样东西：

| 新增 | 作用 |
|---|---|
| 卡片盒 `boxId` | 存在数据库的 `meta` 表里，用来对应两台设备上的同一个卡片盒 |
| 墓碑表 `purged(uid, at)` | 永久删除的卡片也要告诉对方，否则下次同步会被“复活” |
| 同步记录 `peers(deviceId, boxId, lastSync)` | 每个对端上次同步到哪个时间点，下次只交换之后的变更 |

合并按卡片进行：

| 情况 | 结果 |
|---|---|
| 只有一边改过 | 用改过的那份 |
| 两边都改过 | 保留 `updatedAt` 较新的；较旧的那份内容作为“【冲突副本】”闪念放进收件箱 |
| 一边改、一边删（进回收站） | 保留修改，卡片回到正常状态，并在摘要里提示 |
| 一边永久删除 | 两边都删除（墓碑生效） |
| 两边离线时各自新建了同一个编号 | 较晚创建的那张自动顺延到下一个空位（同“续写”规则），摘要里列出新旧编号 |
| 一边改号（整串分支移动） | 每张卡片按上面的规则合并；合并后做一次全盒检查：编号唯一、`[[链接]]` 都能找到 |

## 技术方案

```
发起方 App ──(Bonjour 发现)──▶ 主机 App
   │  加密连接：Noise_XX_25519_ChaChaPoly_SHA256
   │  1. 发起方：我的变更（自上次同步）+ 墓碑 + 全部 (uid, updatedAt) 清单
   │  2. 主机：在自己的页面里调用 ops.mergeBoxes() 合并，写入数据库
   │  3. 主机 → 发起方：对方缺的或较旧的卡片、新的墓碑、摘要
   ▼
发起方写入同样的结果，两边一致
```

| 部分 | macOS / iOS（Swift） | Windows（Rust） |
|---|---|---|
| 发现 | Network.framework `NWListener` / `NWBrowser`，服务类型 `_slipbox._tcp` | `mdns-sd` crate |
| 加密握手 | 用 CryptoKit（Curve25519、ChaChaPoly、SHA256、HKDF）实现 Noise XX | `snow` crate（同一个 Noise 协议，互相兼容） |
| 传输 | 握手后在同一条 TCP 连接上发长度前缀的 JSON 消息 | 同左 |
| 合并 | 页面里的 `ops.mergeBoxes()`（共享 JavaScript） | 同左 |

- 只有“设备与同步”页面打开，或者打开了“保持可被发现”时才监听端口；平时不开任何端口。
- 第一次监听时，Windows 会弹防火墙提示（选“专用网络”），iPhone 会请求“本地网络”权限。
- 浏览器版（`npm run dev`）不能监听端口，不参与同步。
- 卡片盒不大（几千张卡片也只有几 MB），首次同步直接交换全量，之后只交换变更。

## 实现步骤

1. **数据层**：`boxId`、`purged`、`peers`；`ops.mergeBoxes(local, remote, lastSync)` 纯函数，配一组单元测试（每一种冲突都有测试用例）。
2. **Mac 与 iOS 传输**：Bonjour 发现、Noise 握手、消息收发、配对与校验码。
3. **Windows 传输**：同样的协议用 Rust 实现，和 Mac 互相测试。
4. **界面**：“设备与同步”页面、侧栏的同步按钮、同步摘要、配对确认。
5. **CI**：在同一台机器上启动两个实例（不同的数据目录），跑一次完整的“配对 → 各自修改 → 同步 → 比较两边数据”的自测；Mac ↔ Windows 互通在两台真机上手动验证。
6. 发布 **v1.2.0**。

## 暂时不做

- 不在同一个 Wi-Fi 时的远程同步（以后可以通过你自己的网盘文件夹交换加密的变更包）。
- 三台以上设备同时自动同步（两两同步已经能覆盖：手机 ↔ 电脑、电脑 ↔ 另一台电脑）。
- 多人实时协同编辑。

## 待确认

1. **谁当主机**：默认“被点的那一台”当主机。另一种做法是固定一台“主设备”（比如台式机），只要它在线就总是由它合并。
2. **冲突策略**：保留较新的一份 + 冲突副本（推荐），还是每次都让你手动选。
3. **可被发现**：只在“设备与同步”页面打开时可被发现（推荐，更安全），还是常开以便在对方设备上直接点同步。
