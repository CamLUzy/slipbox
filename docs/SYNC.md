# 多端互联：局域网同步

> v1.2 起可用：Windows、macOS、iPhone / iPad 之间任意两台都能同步。

## 一句话

两台设备都打开卡片盒的 **设备与同步**，连在同一个 Wi-Fi 下，**在其中一台点“同步”，另一台就作为主机**。两台之间直接加密传输，几秒钟后两边的卡片盒完全一致。不经过任何服务器，也不需要账号。

## 怎么用

### 第一次：配对（每对设备只做一次）

1. 两台设备都打开 **设备与同步**：侧栏底部的“同步”、菜单 **文件 → 设备与同步…**（<kbd>⌘⇧Y</kbd> / <kbd>Ctrl+Shift+Y</kbd>），或 **设置与数据 → 设备与同步**。iPhone 上在“设置”标签里。
2. “附近的设备”里会出现另一台（显示设备名，比如“lu 的 MacBook Air”“DESKTOP-xxx”“iPhone”）。点 **配对并同步**。
3. 两台设备屏幕上会同时出现一组 **6 位数字**。两边一样，就在两台设备上都点确认。
4. 配对完成后双方记住对方，以后同步不需要再核对数字。

数字由加密握手的结果算出：如果有人在中间冒充，两边看到的数字就会不同。这和蓝牙配对时比对数字是同一个原理。

第一次打开这个页面时：macOS 和 iPhone 会问“是否允许卡片盒查找本地网络上的设备”，请点允许；Windows 防火墙会询问，请允许卡片盒在“专用网络”上通信。

### 日常：点一下就同步

1. 两台设备都打开 **设备与同步**（iPhone 需要在前台）。
2. 在任意一台点 **同步**。
3. 点的这台读取两边的卡片、按下面的规则合并，再把结果写回两边。
4. 结束后显示摘要：两边各新增、更新了几张，有没有冲突副本、改了号的卡片。

找不到对方时（有些路由器禁止设备互相发现），展开“找不到？”，输入对方页面上显示的地址，例如 `192.168.1.20:51515`。

### 同步哪些卡片盒

- 卡片盒按内部 ID 对应，重命名不影响。同步过的卡片盒，点“同步”就直接开始。
- 第一次遇到的卡片盒会先列出来让你勾选：两边同名的“合并为一个”；只有一边有的“复制到对方”或“复制到本机”（空的卡片盒默认不勾）。

## 合并规则

| 情况 | 结果 |
|---|---|
| 只有一边改过 | 用改过的那份 |
| 两边都改过 | 保留较新的；较旧的那份内容作为“【冲突副本】”闪念放进收件箱 |
| 一边改、一边删（进回收站） | 保留修改，卡片回到正常状态，摘要里提示 |
| 一边永久删除 | 两边都删除，以后也不会被同步回来 |
| 两边离线时各自用了同一个编号 | 两台设备都有的那张保留编号（否则是先建的那张）；另一张按“续写”规则顺延到下一个空位，它在同一台设备上新建的分支一起移动，那台设备上指向它的 `[[链接]]` 跟着改，摘要里列出新旧编号 |
| 两边的文献卡片用了同一个文献键 | 后建的那张改为 `键-2`，引用跟着改 |

- **同步前先备份**：两边每次写入前都会自动备份当前卡片盒（和每天的自动备份放在一起），出了问题可以退回。
- “改过”是相对上次和这台设备同步的时间说的，所以两台设备的系统时间要大致准确（默认的自动对时就可以）。

## 技术方案

```
发起方（点“同步”的设备）                     主机
   │  Bonjour / mDNS 找到 _slipbox._tcp
   │  TCP 连接 + Noise_XX_25519_ChaChaPoly_SHA256 握手（双方交换设备信息）
   │  未配对：pair → 主机弹出 6 位数字请用户确认 → paired
   │  hello → 两边的卡片盒列表（名称、boxId、卡片数）
   │  read  → 主机这个卡片盒的全部卡片、墓碑、上次同步时间
   │  页面里的 merge.js 合并
   │  write → 主机写入它缺的卡片和墓碑（写之前先备份）
   ▼  本机写入同样的结果，两边一致
```

| 部分 | macOS / iOS（Swift） | Windows（Rust） |
|---|---|---|
| 发现 | Network.framework `NWListener` / `NWBrowser`，服务类型 `_slipbox._tcp`，TXT：`id`、`n`（名称）、`p`（平台） | `mdns-sd` crate |
| 加密握手 | `apple/Shared/Noise.swift`：用 CryptoKit 实现的 Noise XX | `snow` crate |
| 传输与请求 | `apple/Shared/Sync.swift` | `src-tauri/src/sync.rs` |
| 合并 | `web/js/merge.js`（共享，`tests/merge.test.js`） | 同左 |
| 界面 | `web/js/sync.js`、`web/js/syncview.js` | 同左 |

- **传输格式**：每条 Noise 消息前加 2 字节大端长度。应用消息是 UTF-8 JSON，切成不超过 60000 字节的块，每块一条加密消息，明文第一个字节表示后面还有没有块。
- **配对**：设备身份是一对 Curve25519 密钥，保存在数据文件夹的 `sync.json`。配对码 = SHA-256(`"slipbox-sas"` ‖ 握手哈希) 的前 4 字节 mod 1 000 000。主机只回答已配对、而且公钥没变的设备的 `hello` / `read` / `write`。
- **数据库**：每个卡片盒多了 `meta`（`boxId`、`sync.<设备 ID>`）和 `purged`（墓碑）两张表，见 [数据](DATA.md)。
- **只在页面打开时监听**：离开“设备与同步”页面就停止监听、停止广播，平时不开任何端口。默认端口 51515，被占用时随机选一个。
- **一致性测试**：Swift 和 Rust 的 Noise 实现用同一组测试向量（`tests/noise/main.swift`、`sync.rs` 里的单元测试）逐字节核对；CI 在 macOS 上让 Mac 应用和用同一份 Rust 代码编译的应用互相同步，在 Windows 上让两个打包好的应用互相同步（`scripts/sync-selftest.sh`、`tests/app-sync-*.js`）。
- 浏览器版（`npm run dev`）不能监听端口，不参与同步。

## 暂时不做

- 不在同一个 Wi-Fi 时的远程同步（以后可以通过你自己的网盘文件夹交换加密的变更包）。
- 三台以上设备同时自动同步。两两同步已经能覆盖：手机 ↔ 电脑、电脑 ↔ 另一台电脑。
- 多人实时协同编辑。
